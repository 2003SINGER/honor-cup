# 跨帧墙证据与在线只读定位：2026-10-02 检查点

## 已接通的数据流

离线 `replay_frame_grid_snap.py` 和包内 `m3pro_nav.frame_grid_snap` 现在复用同一墙段拟合与整帧 Manhattan 校正求解器。定位仍按“上次校正位姿 + 本次 odom 相对位移 → 当前帧共同 Δx/Δy/Δyaw”递推。WALL 质量模块只读校正后的逐格边 ROI；当前帧的 WALL 晋升不会反过来证明或修改该帧位姿。40 组合成墙段/位姿的旧求解器与包内求解器逐字段相同；现有 replay 测试也通过。

`NavRuntime` 新增 dry-run 专用的 `FrameGridShadow`：`/scan_multi` 即使因缺逐束时间信息被旧的静止 trust gate 拒绝，仍能进入单独的 shadow 队列，待 odom 源时间有前后样本后每个 planner tick 最多处理一帧。队列上限 32，滞后超过 0.8 s 会记原因并丢弃。它只写 `frame_grid_shadow` 事件，不写导航锚、EdgeMap，也没有 `/cmd_vel` 发布能力；默认 `enabled: false`。旧动态包前 20 个可对齐扫描的纯 Python 本地探针中有 12 帧给出校正提案；每帧耗时中位约 138 ms、最大约 172 ms（本 Mac，非 Orin NX 实测）。这接近约 7 Hz 雷达帧间隔，因此 shadow 的实际丢帧与实时性必须在车端另测，不能凭算力猜测。

`/imu/data_raw` 的陀螺仪 z 可选地参与**扫描预测 yaw 增量**；x/y 平移、控制反馈和格子跨越事件仍用轮式里程计。融合缺样/时戳异常时回退轮式 yaw，`gyro_yaw.enabled` 默认为 false，静止偏置须先标定。曾有一版要求 odom 时刻必须被未来 IMU 样本夹住；按旧动态 bag 前 5,000 条相关消息的实际记录顺序回放，1,546 个后续 odom 区间全部回退 wheel。改为在 `max_age_s` 内因果保持最新角速度后，同样前缀的 1,546 个区间均走 `WHEEL_GYRO` 分支。这个计数只验证回调时序可用，不验证角度方向、偏置或真实角度误差。

## WALL 晋升离线验收

`wall_evidence_quality` 在同一 canonical edge 的相邻扫描中比对实体端点、法向位置与独立视角，并对有真实端点连续性的邻格 ID 突跳 abstain。原地连续帧不会重复提供独立视角 credit。旧完整包的宽松时序门槛得到 62/62 真墙、3 假墙；严格门槛得到 62/62、0 假墙，但短包从 16/18 降至 11/18。详见 [WALL 证据质量报告](2026-10-02-wall-evidence-quality.md)。

`wall_trust_prior` 把实测侧墙可信范围做成 robot-local 软先验：约当前格到前两格高权重，再半格中权重，远处趋严；前墙单独处理。它联同本格连续 ROI、range、MAD、可用时的真实 beam incidence 和转弯 yaw rate 给出晋升权重，**不**把车头相对墙法线当激光入射角，**不**改变 frame snap。完整包先验阈值 1.0 为 62/62、0 假墙，短包只保留 9/18 可观测真墙。没有跨包可接受的生产阈值，模块维持诊断状态。详见 [软先验报告](2026-10-02-wall-trust-prior.md)。

这两组墙证据均依据相同场地、相近日子的已归档手柄包；真值只用于结束后的评分。没有证明新阈值适用于自动行驶、其他摆位或其他拼装误差。`TrustPolicy.diagnostic_only` 保持开启，实跑前置条件未放开。

## 路径剪枝边界

新的 `task_pruned` 若落在**尚未装入 follower 的排队后缀**，运行时可撤销后缀，恢复此前的 cursor/overlay，在既有 WAIT STOP 格边锚重新编译，当前活动 primitive 保持原样。若未来路线已经拼进不可变的 follower 速度剖面，当前只能阻止再延长并记录待处理剪枝；尚不能保证在最近格边截断已安装的路线。这里仍需可取消的未来轨迹与安全再制动接口，不能称为“行驶中发现空枝就立即掉头”。

### 后续可取消轨迹接口设计与验收

把下一版接口定义为“在首个可安全停车的模板检查点替换未来后缀”，而不是任意索引截断。每次 `ActionHorizon` 编译需同时输出有序检查点：模板三元组 `(prev, cell, next)`、精确边中点/中心锚、对应 primitive 边界，以及该点之后的导航检查点快照 `(cursor, plan_state, planned_cells)`。每个快照是独立副本，回滚时不得复用已被后续规划修改的 DFS overlay。模板 primitive 都要带稳定的模板归属和起止检查点；禁止通过浮点坐标猜测模板归属，也不引入斜线连接或几何修补。

Follower 保持已执行历史只读，并显式持有当前计划版本、活动 primitive 索引、该 primitive 内的 measured/reference progress、最近反馈的线速度与时间戳、计划时钟偏移，以及从剩余计划到各检查点的距离/速度约束。收到剪枝后，NavRuntime 找到首条被剪边之前的检查点，从当前实际状态向前检查候选点；只有当从实测速度开始、在不超过 `a_acc`/`a_dec` 和全局速度上限的条件下，能沿原固定模板几何在该点降到零，且反馈仍新鲜、检查点未越过时，才原子地替换 follower 的未来后缀并恢复该点对应 overlay。替换计划必须从检查点零速状态编译；若最近检查点制动距离不足，则保留现有计划并继续报告 pending，直到后续检查点可行或现有计划自然进入 WAIT STOP。不能回写已执行参考，也不能在未完成制动时把新路径从锚点接上。

验收至少覆盖：剪枝目标分别位于直行、ARC、死路折返模板之后；剪枝发生于活动 primitive 中段时活动几何不变，切换点恰为首个可行合法锚；距离充足时以边界速度零切换且速度、加速度界限成立；距离不足/反馈过期/检查点已越过时拒绝替换并维持 pending；overlay/cursor/planned-cells 恢复到被剪边之前的同一个检查点；重编链通过固定模板几何校验且不存在对角修复；连续多个剪枝及重复通知幂等。还要比较切换前 follower 的活动参考前缀，确认它没有被追溯改写。只有这些测试通过并有独立实测轨迹验证制动余量，才可宣称已装入 follower 的未来轨迹可取消；现有实现仍只支持撤销排队后缀与在既有 WAIT STOP 重规划。
