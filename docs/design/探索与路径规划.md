# 探索与路径规划

> 状态：**方案倾向已明确（在线 DFS + 剪枝 + 策略层），细节未定**。这是本题的**核心算法**，也是拉开差距的地方。
>
> 关键前提：迷宫 = 以入口为根的**树形结构**，横平竖直，每格 40 cm，中央有黑引导线。现场公布，不能预输入。

---

## 1. 问题本质

题目说"不限定 DFS/BFS 或其他算法，不按算法名称评分"——翻译过来是：
**别背算法名字，解决真实问题。**

真实问题是：

> 在未知树形迷宫中，以最小化 `总时间 + 漏取罚时` 为目标，
> 决定每一步：往哪走、要不要继续深入、什么时候掉头回出口。

这是一个**在线决策 + 最优停止**问题，不是单纯的图遍历。

---

## 2. 连续问题已被降维成离散图搜索

题面同时给了三个东西：
1. 迷宫是**以入口为根的树**（岔路 = 广度，深入 = 深度）
2. 场地 **7×7，每格 40 cm，横平竖直**
3. 通道正中有**黑色引导线**

→ **不需要激光 SLAM、不需要 Nav2、不需要全局栅格地图。**
→ 只需维护一个 `7×7` 小数组 + DFS 栈 + 节点状态。"建图"两个字可以删掉。

### 节点状态（建议）

```cpp
struct Node {
    int x, y;
    bool visited[4];   // 上右下左
    bool blocked[4];
    int parent_dir;
};
```

每走一格 `x±1 / y±1`，回退直接走父指针。

### 主循环（基线）

```cpp
while (!finished) {
    follow_line();                    // 底置灰度高速循线

    if (detect_intersection())        // 灰度阵列 + 前探判定路口类型
        DFS_handle_node();            // 压栈 / 选分支 / 回退

    if (camera_sees_block())          // 顶部 RGB-D 认色块
        collect_block();

    if (lidar_confirms_deadend() && camera_confirms_no_target())
        prune_and_return();           // 剪枝，提前回头
}
```

## 3. 为什么标准 DFS 不够

- DFS 会把整棵树走完 → 时间最长
- 纯贪心（就近捡）→ 可能漏掉深处高价值方块，吃重罚时
- 关键：**返回出口的时间也是成本**，走得越深，回程越贵

---

## 4. 收益模型（待建立）

对每个未探索分支，估计：

```
净收益 = Σ(该分支期望方块数 × 对应颜色罚时价值)
       − 往返该分支的移动时间
       − 拾取耗时
       − 风险成本（卡死/误判的期望损失）
```

- 罚时系数**现场才给** → 模型必须**参数化**，现场代入，不改代码
- 深度越深 → 往返成本越高，但题面说"深度不同，颜色不同，罚时不同"，
  暗示**深处方块价值更高**。现场拿到规则后立刻算平衡点

---

## 5. 剪枝：什么时候可以直接不进去

**三者同时满足**才可剪（详见 `docs/design/感知与定位.md` P4）：

```
雷达确认前方是 dead end
+ 当前直廊无岔口
+ RGB 在整条可见直廊内没看到方块
→ 剪掉这条叶子走廊
```

> ⚠️ 最容易犯的错：**"这条直线看不到方块" ≠ "这个分支没方块"**。
> 挡板 55 cm 高，车与机械臂也不得超过 55 cm → **看不穿墙**，拐弯后的方块看不到。
> 只有雷达确认是 dead end 才敢剪。

## 6. 必须处理的现实问题

| 问题 | 说明 |
|---|---|
| 死路识别 | 进死路要能识别并折返，不能卡死 |
| 已探索区域记忆 | 树形拓扑：节点 + 边 + 是否已探索 + 是否已收集 |
| 回程路径 | 树上任意节点回根，走父指针即可，不需要搜索 |
| 90° 转弯后重新压线 | 转向后要能重新捕获黑线，这是调试大头 |
| 回退时朝向状态 | 方向状态别乱，否则 DFS 栈与实际位姿脱节 |
| 兜底策略 | 时间超阈值 / 卡死 → **立刻回出口**，保住"有效完成" |
| 地图损毁规避 | 宁可慢，不可撞（撞了本轮 0 分） |

> **最重要的一条**：任何情况下都要保住"有效到达出口"。
> 一个方块都没捡但安全返回 = 有时间分；卡死在场上 = 0。

> 麦轮车理论上可横移/倒着退出，但**高速下 180° 转向后前进可能更稳**，需实测。

### 决策→运动衔接：转弯识别与岔路复用（2026-09-24）

**转弯格识别不靠摄像头、也不需要"提前很久"**：
T-mini Plus 是 360° 旋转扫描，一帧（6–12Hz，~100ms）同时覆盖全向——
进格瞬间按"前墙距离 + 两侧开闭"即可分类（直行/L转/T/十字/死路）；
进格前 0.4~0.6m 前向射线已见前方墙，减速窗口足够。路口分类全面交给雷达，摄像头只管方块和线。

**弧线用在哪（关键区分）**：
- 探索新格：路口决策本来就要在转弯格停留选向（雷达分类+DFS选向），pivot 合理，弧线无收益
- **已知路径（弧线 58% 收益全部在这里）**：回溯、收齐方块后奔出口、回头走岔路——
  格子序列在出发前就全部已知（MazeMap），转弯格位置免传感器先验，
  整条路径可预圆滑成 1/4 圆弧轨迹交给 tracker（`m.path_between` 已有，差"格子序列→米制弧线路径"展开器，
  属 decision_node ⛔ 待填项）

**岔路建模与复用（树已建好）**：
- MazeMap 的 frontier = 岔路表，DFS 栈 = 回溯路径，open_edge/mark_block 全持久化——树形迷宫信息无丢失
- "直接走下一个分支"不需要摄像头：回溯目标格 = 栈顶，path_between 生成已知路径 → arc 走过去，
  到格后按栈选下一个未探分支，继续探索模式
- 死路：雷达三面墙判死 → mark → 栈回溯，回溯段同样全程已知路径
