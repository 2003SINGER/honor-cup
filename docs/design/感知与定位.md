## 1. 要回答的三个问题

| 问题 | 用途 | 精度要求 |
|---|---|---|
| 我在通道里的横向偏移是多少？ | 循迹不剐蹭 | **±9.25 cm，越小越好** |
| 前方是什么？（直行/左转/右转/死角/出口） | 建拓扑图 | 分类正确即可，不需坐标 |
| 方块在哪、什么颜色？ | 拾取 | 能触发拾取动作的精度即可 |

> 核心判断：**不需要全局精确位姿（x, y, θ），需要的是"拓扑正确 + 通道内居中"**。
> 这两件事比 SLAM 简单得多，也稳得多。

## 3. 传感器三分工（建议，见 `hardware/平台硬件.md` 第 4 节）

| 传感器 | 职责 | 为什么是它 |
|---|---|---|
| **底置 8 路灰度/红外** | 高速循迹、横向误差 PID、路口发现 | 黑线在车底，底置阵列直接给偏差，不用跑 OpenCV、延迟小 |
| **顶部 RGB-D** | 提前看方块、认红黄蓝绿、测距、定抓取位 | 有深度，能直接估距离，不用停车看 |
| **双雷达** | 看墙、判死路、通道几何、剪枝与安全兜底 | 判断"前面是墙"比相机猜"好像到头了"可靠 |

> 顶部相机是**高位前视**，有透视变化、曝光/阴影、处理延迟——拿它做高速循线不是最优。
> 三个传感器各干最擅长的事，比让一个 RGB-D 又巡线又认色块合理得多。

## 4. 各模块实现要点

### P1. 循迹
- 底置 8 路：`error = 黑线中心 − 阵列中心` → PID 控底盘
- 备选：顶部相机 ROI 盯黑线（灰度/二值化 → 找黑色区域 → 算中心）
- 目标精度：**±3 cm**（余量 9.25 cm，必须留裕度）

### P2. 路口检测（T / 十字 / L / 死路）
**单排阵列在刚压到路口的瞬间分不出 T 和十字**（两者都可能是 `11111111`）。

解法：越过路口后**用编码器再前进 3~5 cm**，看中间探头：

| 越过后中间探头 | 判定 |
|---|---|
| 仍有黑线 | **十字**（前方纵线继续） |
| 全白 | **T 型**（前方无路，只有左右） |

- 用**编码器增量**控制前探距离，比按时间估稳
- 升级选项：装**前后两排**阵列，免停车探测
- 本题每格 40 cm、路口几何规整，**单排 + 前探足够**

### P3. 方块识别
- `RGB → HSV → 四色阈值 → 找轮廓 → 面积 + 位置`，**连 YOLO 都未必需要**
- 现场光照未知 → **必须做光照鲁棒**：自适应白平衡、多光照样本、防过曝
- 方块自备 → **颜色饱和度高、四色在 HSV 上分离度大**，这是可优化变量

### P4. 剪枝（提前回头）
成立条件（**三者同时满足**才可剪）：

```
雷达确认前方就是 dead end
+ 当前直廊无岔口
+ RGB 在整个可见直廊内没看到方块
→ 这条叶子走廊可以剪掉
```

> ⚠️ **"这条直线看不到方块" ≠ "这个分支没方块"**。
> 挡板高 55 cm，且车与机械臂最高也不能超过 55 cm → **相机看不穿墙**。
> 拐弯后的方块是看不到的。只有确认是 dead end 且整条可见直廊无目标，才敢剪。

## 5. 里程计边界

- 有码盘，但麦轮横移/转弯/打滑会**累积误差**
- 适合：短距离动作控制（"再前进 4 cm"、"转约 90°"）
- **不适合**：只靠码盘跑完整个 7×7
- 组合用法：**灰度纠横向 + 码盘管短距/转角 + 雷达管距离兜底**
