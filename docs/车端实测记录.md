### 关键结论

**0. 缺的不是"没有"，是"没起" —— 启动图景已从源码查清（09-22）**

| 想干什么 | 命令 | 起什么 |
|---|---|---|
| **TF + 雷达融合** | `ros2 launch yahboom_M3Pro_laser laser_driver.launch.py` | ① `ira_laser_tools/laserscan_multi_merger`（`/scan0`+`/scan1` → **`/scan_multi`**）② `yahboom_laser_filter/laser_filter_node` ③ **`M3Pro/launch/display.launch.py`** → `robot_state_publisher`（读 `M3Pro/urdf/M3Pro.urdf`）+ `joint_state_publisher` = **TF 的来源** |
| **相机 + 机械臂解算** | `ros2 launch M3Pro_demo camera_arm_kin.launch.py` | ① `orbbec_camera/launch/dabai_dcw2.launch.py`（Dabai DCW2 驱动）② `arm_kin/kin_srv`（正逆解服务，节点名 `kin_ik_fk`） |
| 里程计融合（可选） | `ros2 launch ekf_bringup ekf.launch.py` | `/odom_raw` + `/imu/data_raw` → `/odom`、`/imu/data` |

> ⚠️ **必须 source 两个工作空间**，因为 launch 跨包依赖：
> `M3Pro_demo`/`yahboom_M3Pro_laser` 在 `yahboomcar_ws`，
> 但它们 include 的 `ira_laser_tools`/`M3Pro` 在 **`M3Pro_ws`**。
> ```bash
> source /opt/ros/humble/setup.bash
> source ~/yahboomcar_ws/install/setup.bash
> source ~/M3Pro_ws/install/setup.bash
> ```

**雷达话题链（`ira_laser_tools/config/laserscan_merge.yaml` 实读）**
```
/scan0 ─┐
        ├─→ laserscan_multi_merger ─→ /scan_multi   (±180°, 量程 0.05~4.0 m)
/scan1 ─┘                            └─→ /merged_cloud
        destination_frame: base_link  ← 所以 TF 不起来，融合必挂
```
`follow_line.py` 用的是**单个 `/scan1`**（只关心前方），不是融合结果。

### 2026-09-22 20:00 · 验证：`laser_driver.launch.py` 跑通 ✅

```bash
source /opt/ros/humble/setup.bash
source ~/yahboomcar_ws/install/setup.bash
source ~/M3Pro_ws/install/setup.bash
ros2 launch yahboom_M3Pro_laser laser_driver.launch.py
```

另一个终端 `ros2 topic list | grep -E "scan|tf|merged"` 输出：

```
/merged_cloud  /scan  /scan0  /scan1  /scan_multi  /tf  /tf_static
```

**结论：一条 launch 就补齐了 TF 树和雷达融合**，与源码反查的图景一致。新增 `scans/tf` 共 5 个话题。

- ✅ `/tf` `/tf_static` —— `robot_state_publisher` + `M3Pro.urdf` 起了
- ✅ `/scan_multi` `/merged_cloud` —— 双雷达融合成功（证明 `base_link` TF 链正确）
- ❓ `/scan` —— **新增，来源未确认**。`/scan0`/`/scan1` 之外多出的这个，
  推测是 `yahboom_laser_filter` 的滤波输出（待用 `ros2 topic info /scan -v` 确认；
  也可能是某个节点订阅融合结果后的转发）。**将来写避障逻辑前必须搞清用哪个。**

**环境起法（日常操作，每次上车都要做）**

```bash
source /opt/ros/humble/setup.bash
source ~/yahboomcar_ws/install/setup.bash
source ~/M3Pro_ws/install/setup.bash      # ← 别漏，ira_laser_tools/M3Pro 在这儿

ros2 launch yahboom_M3Pro_laser laser_driver.launch.py    # TF + 雷达融合（占一个终端）
ros2 launch M3Pro_demo camera_arm_kin.launch.py           # 相机 + 机械臂解算（占另一个终端）
```

**1. 这是"半启动"状态。**
底层板（micro-ROS）+ 手柄程序在跑；**上位机视觉/导航层没起** ——
相机驱动、TF、EKF、Nav2 都不在。开机自启只带起了手柄那一路。

**2. ❌ 没有 `/tf` 和 `/tf_static`。**
来源已查清：`robot_state_publisher` + `M3Pro.urdf`，被 `laser_driver.launch.py` 那条链 include。
**跑一次 `laser_driver.launch.py` 就有了。** 没有 TF = 无法做坐标变换 = 视觉抓取、雷达融合全做不了。

**3. ❌ 没有 `/camera_info`。**
相机内参缺失会直接影响测距与目标定位精度。同样待确认是"没起"还是"真没有"。

**4. 只有 `_raw`，没有融合结果。**
`/odom_raw` `/imu/data_raw` 都在，但没有 `/odom` `/imu/data`
→ EKF 融合节点（`ekf_bringup` 包）没起。
