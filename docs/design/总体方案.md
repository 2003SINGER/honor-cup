## 0. 决策前提（从赛题推出的硬要求）

1. **迷宫现场公布** → 不能硬编码地图，必须在线自主
2. **罚时规则现场公布** → 策略必须对罚时系数鲁棒，最好能现场代入参数
3. **单侧余量 9.25 cm** → 运动控制精度是生死线，不是加分项
4. **迷宫是树形结构，入口为根** → 拓扑已知，只是具体分支未知。可以用树搜索的框架
5. **成绩 = 时间 + 罚时** → 本质是一个**带收益的探索-收集权衡问题**（类似"最优停止"）

## 1. 方案主干：三个子系统

```
感知与定位  →  我在哪 / 周围是什么 / 方块在哪
探索与决策  →  下一步去哪 / 什么时候该放弃回出口
执行与收集  →  怎么走过去 / 怎么把方块带走
```

三者解耦，接口固定，可独立调试与替换。

## 2. 候选路线对比

| 维度 | A. 纯视觉+循迹 | B. 激光雷达 SLAM | C. 循迹移动 + 雷达岔路检测（折中） |
|---|---|---|---|
| 建图需求 | 不需要全局图，只认路口 | 需要在线建图 | 轻量拓扑图（只记节点与分支） |
| 定位精度 | 依赖黑线，通道内很稳 | 依赖特征提取，走廊易退化 | 通道内靠线，路口靠雷达 |
| 探索能力 | 弱，容易迷路/重复走 | 强 | 中上 |
| 调试成本 | **低** | **高** | 中 |
| 失败模式 | 路口判错 → 走错或漏区域 | 走廊退化 → 定位漂移 | 两者都有但都不致命 |
| 54 天可行性 | 高 | 中（风险大） | **中高** |

> **倾向 C，且可以更激进：连"建图"都删掉。**
>
> 依据（来自 `resources/机器人题型分析.md` 与群聊确认）：
> - 题目已把迷宫定义为**以入口为根的树**，通道横平竖直、每格 40 cm、中央有黑引导线
>   → **连续空间问题已被降维成离散图搜索问题**，不需要 SLAM、不需要 Nav2、不需要全局栅格地图
> - 只需维护一个 `7×7` 小数组 + DFS 栈 + 节点状态
> - 雷达从"建图主力"降级为**看墙、判死路、安全兜底**
>
> 判断：B 方案在长直走廊 + 对称结构里雷达退化是经典坑，54 天内调稳 SLAM 还要做收集机构，风险过高。
> **不要为了"看起来高级"上 SLAM。** 这题的胜负手不是建图，是策略与调试。

### 最朴素可跑通的一版（基线，先做出来）

```
巡黑线 → 检测路口 → 维护树/栈 → DFS 探索
       → 相机认颜色 → 记录方块所在节点
       → 机械臂或被动机构收集 → 回退/继续 → 走到出口
```

**先让这一版跑起来，再用剩下的六周优化。**
难度分层（来源：分析记录）：做出来简单 · 稳定跑完中等 · 跑得快有点难 · 进前几主要拼调试和策略。

### 传感器三分工（见 `docs/design/感知与定位.md`）

| 传感器 | 职责 |
|---|---|
| 底置 8 路灰度（建议加装） | 高速循迹、横向 PID、路口发现 |
| 顶部 RGB-D | 提前看方块、认四色、测距、定抓取位 |
| 双雷达 | 看墙、判死路、通道几何、剪枝与安全兜底 |

### 工作量分配（预估，来源：分析记录）

```
算法 / ROS / 电控  60%
视觉感知           20%
调参联调           15%
机械               5%~20%（取决于收集机构复杂度）
```

> **机械很可能最先下班。** 别在机械上过度投入——平台已经把机械臂、底盘、相机都给了。

## 3. 关键设计决策（待定）

### D1. 探索策略
树形迷宫 + 时间计分 → 本质是：**要不要为了深处的方块付出往返时间？**
- 需要建立收益模型：`期望收益 = 该支路方块数 × 颜色价值 - 往返时间成本 - 漏取罚时`
- 罚时规则现场才给 → **策略必须参数化**，现场拿到系数后立刻改参数，不改代码

### D2. 收集时机
- 边探索边捡 vs 先全探索再回头捡
- 后者路径可优化但耗时；前者省路程但可能带错方向

### D3. 容错与卡死恢复
- 必须设计：撞死角怎么办、识别失败怎么办、机械臂失败怎么办
- 原则：**宁可放弃一个方块，不可卡死在场上**（卡死 = 时间无限大）
