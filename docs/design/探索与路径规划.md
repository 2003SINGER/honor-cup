# 探索与路径规划

> 状态：**方案倾向已明确（在线 DFS + 剪枝 + 策略层），细节未定**。这是本题的**核心算法**，也是拉开差距的地方。
>
> 关键前提：迷宫 = 以入口为根的**树形结构**，横平竖直，每格 40 cm，中央有黑引导线。现场公布，不能预输入。

---

## 1. 问题本质

题目说"不限定 DFS/BFS 或其他算法，不按算法名称评分"——翻译过来是：
**别背算法名字，解决真实问题。**

真实问题是：

> 在未知树形迷宫中，以最小化 `总时间 + 漏取罚时` 为目标，
> 决定每一步：往哪走、要不要继续深入、什么时候掉头回出口。

这是一个**在线决策 + 最优停止**问题，不是单纯的图遍历。

---

## 2. 连续问题已被降维成离散图搜索

题面同时给了三个东西：
1. 迷宫是**以入口为根的树**（岔路 = 广度，深入 = 深度）
2. 场地 **7×7，每格 40 cm，横平竖直**
3. 通道正中有**黑色引导线**

→ **不需要激光 SLAM、不需要 Nav2、不需要全局栅格地图。**
→ 只需维护一个 `7×7` 小数组 + DFS 栈 + 节点状态。"建图"两个字可以删掉。

### 节点状态（建议）

```cpp
struct Node {
    int x, y;
    bool visited[4];   // 上右下左
    bool blocked[4];
    int parent_dir;
};
```

每走一格 `x±1 / y±1`，回退直接走父指针。

### 主循环（基线）

```cpp
while (!finished) {
    follow_line();                    // 底置灰度高速循线

    if (detect_intersection())        // 灰度阵列 + 前探判定路口类型
        DFS_handle_node();            // 压栈 / 选分支 / 回退

    if (camera_sees_block())          // 顶部 RGB-D 认色块
        collect_block();

    if (lidar_confirms_deadend() && camera_confirms_no_target())
        prune_and_return();           // 剪枝，提前回头
}
```

## 3. 为什么标准 DFS 不够

- DFS 会把整棵树走完 → 时间最长
- 纯贪心（就近捡）→ 可能漏掉深处高价值方块，吃重罚时
- 关键：**返回出口的时间也是成本**，走得越深，回程越贵

---

## 4. 收益模型（待建立）

对每个未探索分支，估计：

```
净收益 = Σ(该分支期望方块数 × 对应颜色罚时价值)
       − 往返该分支的移动时间
       − 拾取耗时
       − 风险成本（卡死/误判的期望损失）
```

- 罚时系数**现场才给** → 模型必须**参数化**，现场代入，不改代码
- 深度越深 → 往返成本越高，但题面说"深度不同，颜色不同，罚时不同"，
  暗示**深处方块价值更高**。现场拿到规则后立刻算平衡点

---

## 5. 剪枝：什么时候可以直接不进去

**三者同时满足**才可剪（详见 `docs/design/感知与定位.md` P4）：

```
雷达确认前方是 dead end
+ 当前直廊无岔口
+ RGB 在整条可见直廊内没看到方块
→ 剪掉这条叶子走廊
```

> ⚠️ 最容易犯的错：**"这条直线看不到方块" ≠ "这个分支没方块"**。
> 挡板 55 cm 高，车与机械臂也不得超过 55 cm → **看不穿墙**，拐弯后的方块看不到。
> 只有雷达确认是 dead end 才敢剪。

## 6. 必须处理的现实问题

| 问题 | 说明 |
|---|---|
| 死路识别 | 进死路要能识别并折返，不能卡死 |
| 已探索区域记忆 | 树形拓扑：节点 + 边 + 是否已探索 + 是否已收集 |
| 回程路径 | 树上任意节点回根，走父指针即可，不需要搜索 |
| 90° 转弯后重新压线 | 转向后要能重新捕获黑线，这是调试大头 |
| 回退时朝向状态 | 方向状态别乱，否则 DFS 栈与实际位姿脱节 |
| 兜底策略 | 时间超阈值 / 卡死 → **立刻回出口**，保住"有效完成" |
| 地图损毁规避 | 宁可慢，不可撞（撞了本轮 0 分） |

> **最重要的一条**：任何情况下都要保住"有效到达出口"。
> 一个方块都没捡但安全返回 = 有时间分；卡死在场上 = 0。

> 麦轮车理论上可横移/倒着退出，但**高速下 180° 转向后前进可能更稳**，需实测。

### 专项调研：Micromouse 的"边走边学+快速跑"方法论（2026-09-24，官方路网文档+开源社区）

**官方路网导航（5.路网规划导航）给的可借点**：nav2 RPP 纯追踪——**曲率动态缩放速度**
（弯道自动降速）+ **前瞻距离随速度动态变化**（快了看得远）。与我们的 tracker 同族，
确认了"弧线段限速=曲率函数"是正统做法，不是野路子。

**Micromouse 社区（最成熟的"边走边知道"参照系）四条硬结论**：

1. **探索阶段就能变速**：冠军鼠标搜索阶段直道 1.1m/s、转弯 0.7m/s，
   秘诀是**提前 3cm 读墙**给减速留距离（v²-u²=2as 算刹车点）。
   → 我们：探索时已知走廊段（回溯、复访）可跑 0.3+，接近未知格才降到 0.2；
   雷达前向射线就是"提前读墙"，刹车点可预计算
2. **弧线轨迹 = 运动基元拼接 + 梯形/S 曲线速度剖面**：直道全速，弯前按
   v_arc=√(a_lat·r) 预减速，刹车点=(v²-v_arc²)/2a 预计算——我们的弧线展开器
   应输出**带速度剖面的轨迹**而不只是几何路点（几何我们已有，速度剖面是纯代码新增）
3. **最快路径 ≠ 最短路径**（2017 全日本冠军 Red Comet：多走 5.5m 少转弯取胜）：
   path_between 应按**时间代价**（转弯计价）而非格数——但注意**树形迷宫两格间路径唯一**，
   此条仅当真实赛场有环路时生效，MazeMap 反正都支持
4. **flood-fill 引导探索 vs DFS**：flood-fill 按到目标的距离梯度选下一个未探格，
   回溯更少；我们 7×7 树形迷宫 + 8 方块 + 出口早停，DFS 栈已够用，
   但可加 flood-fill 引导作仿真对比实验（纯仿真可测）

**回程即完善地图**：micromouse 惯用"利用回程继续完善地图，不探全图就能锁定最短路径"
——与我们"收齐+见出口→直奔出口"同构，且回程走的是已知路径 → 全程弧线+变速。

### 流式探索：边扫边当已知（2026-09-24，用户方案，取代"路口必须停"）

**核心**：地图数据一到手就直接当已知路径——不存在"探索模式=慢速"的硬性区分，
探索速度由**前视确认视界 d_conf** 决定，闭环调度：

1. **流式置信建图**：每帧扫描持续更新 MazeMap 边置信（unknown → suspect → confirmed，
   按入射角+距离分置信——正入射远也可信，掠射近了才可信）
2. **弧线提前承诺**：下一格分类一置信就立即排弧线。例：前方格远边墙（正入射，远也准）
   + 右侧墙确认 → 该格 = 左转 L → 中途就排左弧线滑过，不等进格
3. **速度调度**：v ≤ √(2·a_dec·(d_conf − margin))——下一个未分类路口的确认视界
   决定当前允许速度；长直道中段视界内全分类完 → 全速；视界缩到刹车距离内 → 减速蠕行
4. **几何量化（支撑"远处侧墙不可信"的怀疑）**：侧墙边缘的定位误差 ≈ 0.2/sin²φ·δφ
   （φ=射线与墙法线夹角，δφ≈0.3° 角噪声）。0.8m（2格）误差 ~2cm 可信；
   1.6m（4格）~6.5cm 勉强；2.4m（6格）~10-15cm **超过半格，不可信**。
   且 TOF ±20mm 是正入射规格，掠射回波更弱更差。
   → **d_conf ≈ 3~4 格（侧向）/ 更远（正前向）是几何预估值，必须实测修正**
5. **实测项（唯一要测的）**：真实 d_conf(方向, 距离) 曲线——不同距离/入射角下
   墙沿定位误差与回波质量，直接决定探索巡航速度与减速时机

**型号实锤（官方 PDF）**：T-mini Plus，360° 2D 旋转扫描，测距精度 ±20mm。
双雷达（左后+右前对角）不是补 360°——单只就是 360°，
是为**互相补安装盲区 + 近场盲区 + 冗余**，ira_laser_tools 合并为单一 scan。
