# 固定轨迹到下位机：控制链与校准边界

本文件记录 **2026-09-26 本地源码审计与确定性运动门槛**。它说明控制软件
的边界和待实测参数；五项模拟动作通过不等于实车已验收。

## 1. 当前控制链

```text
ActionHorizon / MotionPlanner → 固定 STRAIGHT / R=0.2 四分之一圆 / STOP
  → SpeedProfile（速度上限、段末上限、制动前后传播）
  → TrajectoryReference（p_ref、世界系 v_ff、固定 yaw_ref）
  → PositionController（位置 P / 可选速度 D、独立 yaw hold）
  → 车体系 Twist(vx, vy, wz)
  → /cmd_vel → 下位 Motion_Ctrl_Car → 四轮增量 PID → PWM
  → 电机/编码器 → 实际 Twist → Pose
```

新链条的纯 Python 接口在 `software/ros2/m3pro_nav/m3pro_nav/`：
`speed_profile.py`、`trajectory_reference.py`、`position_controller.py`、
`control_chain.py` 和 `plant.py`。`software/sim/motion_gate.py` 只跑五项固定
机动。`runtime_v2.py` 仍使用 `MotionExecutor` 做 Tier A 理想几何任务回归，
没有把未标定的电机模型塞进随机迷宫 Gate。旧 `tracker.py` 会让车头随行进
方向旋转且未被当前运行时使用，已从活动代码删除；历史实现仍在 Git 历史。

`SpeedProfile` 把每段 `v_end` 视为接缝速度上限，先向后传播制动界，再向前
传播加速界；STOP 与折返零速按模板给定。这样从静止通过 0.2 m 根入口段
不会被迫瞬间达到 `0.7 m/s`。参考轨迹只采样既有模板，不改几何、弯道半径
或车身朝向。位置环输出世界系前馈加误差修正后，再用测量 yaw 变换为车体系。
它不含积分项。`ControlChain` 上位周期显式配置为 20 ms；下位仿真只在源码
规定的 10 ms tick 更新，命令在两次上位更新之间保持。

## 2. 本地下位机源码事实

原始资料是仓库本地未跟踪的
`24.程序源码汇总/控制板基础例程.zip`，SHA-256：
`26400e0a6cf7e13a74404b74c9c707482f59ecddd6199f12f720b7ead5ca20f1`。
以下路径均在压缩包的 `Board_Samples/Microros_Samples/Subscriber_twist/APP/`
之下。行号是压缩包内源码行号；可用 `unzip -p` 复核。此例程是可读的实现
依据，是否与实车已烧录固件完全相同仍需上车核对。

| 项目 | 源码证据 | 仿真处理 |
|---|---|---|
| 任务周期 | `app.c:29-42` 的 `vTaskDelayUntil(..., 10)`；`app_motion.c:265-275` 明写每 10 ms 调用 `Motion_Handle` | 固定 10 ms 下位 tick |
| ROS 输入 | `ros2_handle.c:198-202` 从 Twist 的 `linear.x/y`、`angular.z` 调 `Motion_Ctrl_Car` | 车体系 `Twist2D` 输入 |
| 输入与四轮限制 | `app_motion.h:20-24` 为 x/y ±0.7 m/s、z ±4.2 rad/s、轮速 ±750 mm/s；`app_motion.c:26-65,177-212` 先限三轴、转整数 mm/s 再麦轮逆解并逐轮限幅 | 镜像相同界限、整数截断和轮序 |
| 轮序/运动学 | `app_motion.c:179-203`：M1..M4 = `(vx−vy−ωA, vx+vy−ωA, vx+vy+ωA, vx−vy+ωA)`，A=0.167 m；`120-134` 给出对应正解 | `plant.py` 镜像逆解与正解 |
| 编码器速度 | `app_encoder.h:7-9` 为 2464 pulse/rev；`app_motion.h:8-13` 为轮周长 0.2513 m 与 A=0.167 m；`app_motion.c:120-142,163-172` 用 10 ms 脉冲差算轮速 | 量化脉冲后反馈 PID |
| 四轮速度 PID | `app_pid.h:6-8` 为 Kp=0.8、Ki=0.06、Kd=0.5；`app_pid.c:26-37` 用增量式误差差分，输出钳位 ±1000 | 镜像差分与限幅；不凭空加外环积分 |
| PWM | `app_motor.h:6-8` 为非零输出加 1000 pulse、硬限 ±2000；`app_motor.c:19-31,68-74` 执行补偿与限幅 | 镜像补偿；真实物理死区另列未标定 |
| 零速 | `app_motion.c:183-187` 调 `Motion_Stop(STOP_BRAKE)`，相关状态清零见 `app_motion.c:90-98` | 清 PID 命令；电机刹车的真实减速仍属模型假设 |

滤波。PWM 后的电气、摩擦、地面滑移和实车延迟不在压缩包中。

## 3. 模拟假设与实测入口

`IdealPlant` 执行命令 Twist 的理想位姿积分，供纯算法对照。
`LowerLoopPlant` 镜像上述固件控制流程，但 PWM→真实轮速只能用最小
一阶响应。**UNCALIBRATED / SIM_ASSUMPTION**：

- `motor_tau_s=0.12`、`motor_gain_mm_s_per_pwm=1.0`、物理 PWM 死区
  `physical_deadzone_pwm=1000`。其中固件补偿的 1000 是源码事实，物理
  死区是否正好 1000 不是。
- 上位 `upper_period=0.02 s`、位置 P/D 和 yaw P/D 的默认增益，以及
  `SpeedProfile` 的加减速上限 1 m/s² 都是暂用控制配置。
- 当前没有实测通信延迟、PWM→轮速阶跃曲线、横移与纵移差异、四轮不一致、
  地面滑移、定位噪声或真实车体动态净空。

下一步用**实际已烧录固件**先做只读版本/接口核对；在安全场地按小幅
`/cmd_vel` 阶跃记录命令时间戳、四轮 encoder、`/odom_raw` 与 IMU。由数据
拟合延迟、时间常数、增益、最大轮速/加速度、死区和四轮差异，替换上述
假设。参数与 CSV 日志格式须在实测前固定，避免用比赛结果倒调仿真。

## 4. 确定性门槛与停止条件

运行 `python3 software/sim/motion_gate.py --backend lower` 输出五项：直行、
纯横移、直行接左弧接直行、右弧对应动作，以及左弧接直行接右弧接折返。
每项记录 RMS 位置误差、最大横向误差、最大 yaw 误差、最大轮 RPM、
最大轮加速度（RPM/s）、RMS 速度误差、最小计算墙净空与碰撞次数。
`software/tests/test_motion_gate.py` 对碰撞、轮速、偏差和净空设了当前
模拟配置的确定性门槛。此门槛只判断模块衔接和明显失稳，不用于宣称真实
硬件参数或车体 swept-OBB 已验收。测试默认单进程，不跑大规模随机迷宫。

仿真在这五项通过后即停；真实传感器可信范围、地图剪枝收益和雷达归属
留到各自测量阶段。

## 5. ROS 驱动接入入口（尚未实车执行）

`m3pro_nav` 现有 `driver_probe` 可执行项。原 `m3pro.launch.py` 指向不存在的
`decision` 节点并传旧 `pivot|holo|arc` 模式，已改成**默认只读**的探针。
探针记录 `/cmd_vel`、`/odom_raw`、`/imu/data_raw` 到 CSV；只读模式没有
`/cmd_vel` 发布者。数据字段包括接收单调时钟、消息时间戳、里程计位姿与
速度、IMU 角速度/加速度、实际观察到的命令，以及本节点发送的命令。

```bash
# 在已 source ROS Humble 与项目工作空间的车端，仅观察、不会动车
ros2 launch m3pro_nav m3pro.launch.py

# 仅在安全场地、确认无其他 /cmd_vel 发布者后显式发一次很小的阶跃
ros2 run m3pro_nav driver_probe --execute --axis x \
  --magnitude 0.05 --duration 0.5 --csv /tmp/m3pro_x_step.csv
```

执行模式把线速度幅值限在 0.05 m/s、角速度幅值限在 0.15 rad/s、时长限在
0.5 s；正负号选择方向。它在发命令前检查 `/odom_raw` 与 `/imu/data_raw`
接收时间是否新鲜，并拒绝已有其他 `/cmd_vel` 发布者；结束或异常时发零速，
再固定记录短暂响应。**这些只是代码内安全门槛，当前 Mac 未装 ROS，且尚未
在车端执行；不能据此声称完整驱动链已经打通。**实车前还需核对手柄发布者、
已烧录固件、车轮离地或场地净空，以及实际话题类型。车端已观察到的原始
话题与启动环境以 `docs/车端实测记录.md` 为准。

新增 `control_probe` 作为位置环接官方 `/cmd_vel` 的小距离试验入口，**不在
默认 launch 中启动**。安装本分支 ROS 包后，它默认只订阅并记录 `/odom_raw`、`/imu/data_raw`、
`/cmd_vel` 的消息时间戳、frame、里程计位姿和速度；无 `--execute` 时不创建
`/cmd_vel` publisher。先在车端只读运行，取得实际的 `header.frame_id`、
`child_frame_id`、消息频率和方向，再决定是否使用下面的执行模式：

```bash
# 车端已 source ROS Humble 与两个工作空间；只读记录，Ctrl-C 结束
ros2 run m3pro_nav control_probe --csv /tmp/m3pro_control_readonly.csv

# 仅在实际 frame 与速度方向已核验、手柄/其他发布者已停、底盘架空或有安全净空后
# 把 FRAME_FROM_CSV 替换为本车实测值；仍需人工显式 --execute
ros2 run m3pro_nav control_probe --execute \
  --expected-odom-frame FRAME_FROM_CSV \
  --expected-base-frame CHILD_FRAME_FROM_CSV \
  --axis x --distance 0.02 --csv /tmp/m3pro_control_x_trial.csv
```

执行试验沿启动时的车体 x 或 y 轴生成不超过 0.03 m 的局部直线，复用
`SpeedProfile → TrajectoryReference → PositionController`，固定车身 yaw；
再通过 `RigidFrameTransform` 用同一物理起点在局部/里程计两系的显式锚定
位姿，把**采样后的参考**变换到 Odometry 世界系，输出车体系 `Twist`。
固定模板本身仍留在轴对齐的规划坐标系，不能为了坐标转换构造斜线
`MotionPrimitive`；`REVERSE` 也与 `STRAIGHT` 共用轴对齐构造校验。
迷宫坐标与实车 odom 的初始对准还没有上车核验。原始 Odometry
的 `pose` 按 `header.frame_id`、`twist` 按 `child_frame_id` 的
[ROS Odometry 消息约定](https://github.com/ros2/common_interfaces/blob/rolling/nav_msgs/msg/Odometry.msg)
解释，**本车是否遵守该约定仍须现场核验**。原始 IMU 的轴向也未核验，
当前仅作新鲜度门槛与日志，不直接作 yaw-rate 反馈。

执行入口要求显式 frame、有效且递增的消息时间戳、反馈接收新鲜、没有
其他 `/cmd_vel` publisher；把平移命令模长限制在 0.05 m/s、偏航速度限制
在 0.15 rad/s，并在试验结束或异常后尝试连续发零命令 0.5 s。位置增益和试验
加减速仍是 **UNCALIBRATED / SIM_ASSUMPTION**。这只是闭环接口试验，
尚未把迷宫 Action Horizon、真实雷达或方块观测接到 ROS 执行器。
