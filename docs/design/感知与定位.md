## 1. 要回答的三个问题

| 问题 | 用途 | 精度要求 |
|---|---|---|
| 我在通道里的横向偏移是多少？ | 循迹不剐蹭 | **±9.25 cm，越小越好** |
| 前方是什么？（直行/左转/右转/死角/出口） | 建拓扑图 | 分类正确即可，不需坐标 |
| 方块在哪、什么颜色？ | 拾取 | 能触发拾取动作的精度即可 |

> 核心判断：**不需要全局精确位姿（x, y, θ），需要的是"拓扑正确 + 通道内居中"**。
> 这两件事比 SLAM 简单得多，也稳得多。

## 4. 各模块实现要点

### P1. 循迹
- **主方案（已定 09-23）**：官方 `follow_line`（顶部相机 HSV → 二值化 → PID），加红外阵列方案取消
  - 缓解视野盲区：调相机俯角（若可调）+ 裁 ROI + 参数整定
  - HSV 必须现场重标（`Roi_hsv()`，黑胶布 ≠ 默认彩色线阈值）
- 目标精度：**±3 cm**（余量 9.25 cm，必须留裕度）
- **前置条件**：需先知道**黑色电工胶布的实际宽度**（决定 ROI 高度与路口判定参数）

### P2. 路口检测（T / 十字 / L / 死路）
**单排阵列在刚压到路口的瞬间分不出 T 和十字**（两者都可能是 `11111111`）。

解法：越过路口后**用编码器再前进 3~5 cm**，看中间探头：

| 越过后中间探头 | 判定 |
|---|---|
| 仍有黑线 | **十字**（前方纵线继续） |
| 全白 | **T 型**（前方无路，只有左右） |

- 用**编码器增量**控制前探距离，比按时间估稳
- 升级选项：装**前后两排**阵列，免停车探测
- 本题每格 40 cm、路口几何规整，**单排 + 前探足够**

### P3. 方块识别
- `RGB → HSV → 四色阈值 → 找轮廓 → 面积 + 位置`，**连 YOLO 都未必需要**
- 现场光照未知 → **必须做光照鲁棒**：自适应白平衡、多光照样本、防过曝
- 方块自备 → **颜色饱和度高、四色在 HSV 上分离度大**，这是可优化变量

### P4. 剪枝（提前回头）
成立条件（**三者同时满足**才可剪）：

```
雷达确认前方就是 dead end
+ 当前直廊无岔口
+ RGB 在整个可见直廊内没看到方块
→ 这条叶子走廊可以剪掉
```

> ⚠️ **"这条直线看不到方块" ≠ "这个分支没方块"**。
> 挡板高 55 cm，且车与机械臂最高也不能超过 55 cm → **相机看不穿墙**。
> 拐弯后的方块是看不到的。只有确认是 dead end 且整条可见直廊无目标，才敢剪。

## 7. 数据流分层（2026-09-23 定稿）

```
决策层（MazeMap + 雷达定位）      ← 路口级：我在哪个格、frontier、回终点路径
    ↓ 目标（拐哪个方向 / 巡线开跑 / 丢线兜底导航）
巡线 PID（相机 follow_line）      ← 30Hz：只看黑线偏差，压横向
    ↓ /cmd_vel
STM32 轮速环（FreeRTOS 10ms）     ← 速度环：只管轮子转到位
```

**解耦原则**：
- 雷达定位**不反馈**给巡线 PID（巡线只认黑线偏差）——它的服务对象是决策层
- 雷达定位的两个用途：① 探索决策（走过哪 / frontier / 回终点）② **丢线兜底**——
  丢线时用"当前格 + 墙吸附"导航到最近路口，这是没有定位时做不到的
- 底盘是**速度环**（轮速 PID），不感知位置；"位置"拆为横向（巡线管）与纵向/拓扑（决策层管）

## 8. 雷达规格（官方 PDF 实读，2026-09-23 补全）

来源：`2.激光雷达/1.雷达简介与使用/雷达简介与使用.pdf`。型号 **T-mini Plus**（DTOF，串口 230400 直连 STM32 UART4）：

| 参数 | 官方值 | 意义 |
|---|---|---|
| 扫描角度 | **0-360° 全向** | FOV 无限制，任意方向可观测，仿真 idx%2 分配合法 |
| 测距范围 | 0.05-12m | 启动一次扫描可看穿大半迷宫（ROS merge 层截断在 4m，可放宽） |
| 扫描频率 | 6-12Hz | 实测 7.15Hz ✓ |
| 测距精度 | 20mm | 仿真 σ=1cm 假设合理，回填用实测 |
| 角度分辨率 | 0.54° | 足够 |
| 俯仰角 | 0-1.5° | 扫描面近水平(12.5cm 高)——确认扫不到矮方块 |
| **话题映射** | **/scan0=左后，/scan1=右前** | 官方原文明确，与 URDF laser0/laser1 对齐 ✓

**不转向横移方案（麦轮原生支持，位置环解锁）**：
- 纯位置环导航时车体可全程不旋转：N 走完直接横移 E
- 好处：相机朝向恒定 → 标定/PID 永不重调；省掉全部旋转时间
- 代价：横移时相机看不了线（纯位置模式下无影响，巡线保底只在沿轴移动时可用）

**纯里程计够不够**：仿真 raw 模式（无吸附）30m 漂 0.845m > 半格——不够。
但 +3% 比例误差是占位值，出厂标定后可能 ~0.5%（30m 漂 15cm）——仍贴危险线，
且一次打滑就超。结论：雷达吸附必须保留，实际校正量等日志回填。

### 深度增强巡线：线的米制偏差（2026-09-23，Phase 3 素材）

DCW2 深度精度 <1%@1m（官方），可以把线从"像素偏差"升级为"米制横向偏差"：
RGB 检出线像素 → 深度 → 相机系 3D 点 → TF(DCW2) → 地图系。
**黑线在地图系的位置是先验已知的（走廊中线）** → 测得线位置 = 测得车的横向位置，亚厘米无漂移。

两个物理坑与对策：
1. **黑色胶布吸收结构光红外** → 线像素处深度缺失/不可靠
   → 对策 A：取线两侧地面点深度（等价）；对策 B（优先）：**地面平面投影**——
   地面已知平面 + 相机内参 + 安装高度(URDF DCW2 z) → 像素行 ↔ 地面距离纯几何换算，零深度依赖
2. 结构光有效距离短（典型 ~1.5m）——巡线只看前方 0.3~1m，恰在有效区

边界：**纵向不可观**（线是连续直线，沿线方向位置读不出）——纵向仍靠路口事件 + 雷达。
落点：Phase 3 融合控制器的横向误差信号用"线的米制偏差"（优于雷达 4cm），纵向用路口+雷达。

### ⚠️ 相机装在机械臂上——外参不稳定问题与对策（2026-09-23，URDF 实锤）

`DCW2_Joint` 父连杆 = **arm4**（xyz −0.048, 0.002, 0.067 相对 arm4）——DCW2 随臂动，不在车体上。
臂晃 → 相机外参变 → 地面投影/米制换算被污染。对策四层：

1. **行驶时臂收进固定停放姿态**：外参恒定可一次性标定；振动是高频瞬态，低通滤波压掉。
   附带收益：重心更低、宽度更小（21.5cm 约束更安全）
2. **外参从 TF 实时查**：arm1~5 关节状态在 /tf 动态发布，`lookup_transform("base_link","DCW2")`
   拿当前姿态下的真实外参，不写死
3. **在线自标定**：迷宫几何是现成标定靶（墙 ±0.2m、线在中线全是已知量），
   用观测反推相机实际俯仰/偏航，吃掉舵机齿隙与结构柔性（残余 ~1cm 级）
4. **误差预算**：对策后残余 = 振动噪声(可滤) + 标定残差(~1cm)——仍优于雷达定位的 4cm，
   横向位置信号首选相机

另：车上的 follow_line.py 与官方 zip 内容一致（仅 CRLF/LF 差异），读哪个都一样。

### reg 吸附的三个已知坑与升级方向（2026-09-24，用户质疑后自查）

现状：`maze_sim.py` reg 模式是**简化验证**（逐轴、恒速直线、真值航向）。工程化前必须补：

1. **方向性置信门限**：侧向掠射噪声大 → gate 放宽或降权；前向正对测距准 → gate 收紧。
   上场实测前/侧向残差分布后定数值（`m3.sh log` 采数据）
2. **预测门限取代硬 round**：用里程计+航向先验预测期望墙坐标，在预测附近小门限内才吸附；
   不再依赖 round 最近邻（漂移近半格时 round 会选错格线，现在只能靠丢弃被动兜底）
3. **航向误差（最硬的坑）**：仿真观测轴用真值航向=作弊；实车转弯后轴建错→吸附整体歪。
   对策：IMU 短期航向 + 直行段"侧墙正交于行进轴"校准航向漂移

### 雷达实测规格与开源定位算法选型（2026-09-24 调研）

**雷达型号确认：YDLIDAR T-mini Plus**（亚博官方，×2 对角布局）——是 360° 旋转扫描雷达（非单点）：
0.05–12m（80% 反射率）/ 0.05–4m（10%），**相对误差 ±20mm 全量程恒定**（非比例误差），
4000Hz 采样、0.54° 角分辨率、6–12Hz 扫描帧率。
→ 场地 ≤2.8m，正对入射时测距噪声 ~2cm（此前仿真取 4cm 是保守值，可收紧到 2cm）；
  10% 反射率量程 4m 对 2.8m 场地仍够用。

**开源算法调研结论**（场景 = 已知格线墙登记册 + 里程计 + IMU + 在线增量地图）：
- CSM（Cartographer 实时相关匹配）/ hector（高斯牛顿 scan-to-map）：通用但为建图设计，地图连续，不利用我们的离散先验
- AMCL 粒子滤波：文献证实**对称环境下退化**（正确率 84%→90%），7×7 树形迷宫高度对称，不宜作主方案
- Hybrid SLAM（odom+IMU+EKF）在对称环境正确率 98–99%（Robotica 2025 综述）——方向正确
- **选型：RANSAC 线段提取 + EKF 吸附 + Mahalanobis 门限**（即"按坐标+移动趋势预测"的教科书形态）：
  1. 预测：odom+IMU → 预测位姿与协方差（移动趋势）
  2. 观测：全扫描 RANSAC 提墙线段，算每段入射角——正入射段置信高，**掠射段降权/丢弃**（方向性置信）
  3. 关联：预测位姿把观测投到地图系，与登记册格线算马氏距离，门限内才关联（不搜索匹配）
  4. 更新：只修墙法线方向分量，增益按置信度加权（x/y 轴解耦）
  5. **离散一致性终检（防吸错格子的最后一道闸）**：吸附后的格子必须与 MazeMap 当前格子及已确认墙一致；
     不一致 → 拒绝本次吸附并告警。吸错的唯一途径是漂移>半格且决策层不知情——决策层本来就知道自己在哪格，
     定位只需修米制误差，这道闸把残余风险封死
- Cartographer/slam_toolbox 平台官方课程自带，可作独立校验工具，不作主方案（过重）

### 航向校准：墙做绝对基准，先航向后位置（2026-09-24）

迷宫墙全部横平竖直（格线系）→ **墙是航向的绝对参考**：

- **直行段校航向**：RANSAC 拟合侧墙线段的角度，与格线系先验（0°/90°）求偏差 = 当前航向误差。
  单点角分辨率 0.54°，但一条墙段数百点拟合 → 线角度精度 <0.1°，足够。
- **直行一致性互检**：沿 y 走时 x 应不变——编码器 x 出现持续漂移 = 航向有误差（交叉耦合），
  反过来也校 x/y 里程计比例误差。IMU 陀螺仪管高频变化（转弯角速度），墙管低频绝对基准，互补滤波。
- **顺序必须先航向后位置**：航向误差会把里程计外推整个转歪。
  量化：1° 航向误差 × 2.8m 全场路径 ≈ 4.9cm 横向漂移（2° ≈ 9.8cm）——
  航向不压到 1° 内，位置门限再紧也没用。所以每次更新先修 θ，再修 x/y。
- **转向后重锚定**：90° 转弯完成后航向应吸附到最近的轴（±容差），IMU 积分的转角
  与"应转 90°"的差 = 陀螺刻度误差，顺手标定；位置 x/y 随新航向重新外推。
- 各源分工汇总：IMU=高频短期，墙=低频绝对，编码器=相对位移+一致性互检，MazeMap=离散终检。
