# 2026-09-30 车端静态雷达观测记录

## 目的与边界

这批数据检查静止姿态下 `/scan_multi` 射线能否投影并关联到给定迷宫网格边。`scan_debug` 是只读观测：它验证的是几何投影、边关联和诊断统计，不驱动车辆，也不执行基于墙面的位姿校正。当前没有证据证明系统能把车位姿“吸附”到墙或格子；静态关联结果也不能直接当作可信地图。

坐标采用本场地约定：从调试椅方向看，N 向上并朝入口内侧、E 向右；7×7 零起始网格，左下角为 `(0,0)`。这是场地相对坐标，不是地理罗盘方向。采集记录中的 `heading: N` 是传给程序的姿态标签，不独立证明车辆实际朝向。

- `(1,2)`：N、E 通；S、W 为墙。从 `(1,2)` 连续走 N、N 到 `(1,4)` 终止，确认该端为死端墙；从 `(1,2)` 走 N、W、N 到 `(0,4)`，在 RViz 可见 `(0,4)` 北边界墙的一部分。

## 已发现的问题与代码处理

现场复核表明，不能把每条射线各自算出的 OPEN/WALL 结果直接累加：同一扫描内不同射线可能对同一边产生冲突，且落在理想网格外缘附近的射线可能把外框误报为 OPEN。当前工作区的关联代码增加了三项冲突抑制：近外框半格内不把外框穿越记作 OPEN；同一条 UNIQUE 命中不再同时投 OPEN；同一帧任一 UNIQUE 墙命中会否决该帧对同边的 OPEN 投票。适配层也丢弃与已接受 WALL 命中同边的 OPEN 证据。

这些改动针对已观察到的冲突，但仍是待验修复：半格外框保护是临时规则，需以实测场地边界替代；现有数据汇总是在修复前生成的，不能证明修复后已通过接受标准。后续必须用原始 bag 离线重放、对照已确认路径真值并审查逐帧/逐射线结果。

工作区另有独立的纯 Python `pose_correction` 离线提案模块：它要求调用方提供当前位姿、实际命中端点和已确认的有限墙段（墙段可按实测弯折处分段），在多方向墙段、残差、内点比例及位姿改变量门限均通过时才返回候选位姿；它不修改位姿或地图。当前 `frames.jsonl` 只保存聚合统计，不含逐射线端点，无法直接用于该模块。复核实车 session 需要从 rosbag 读取 LaserScan、odom 与 TF/外参，用相同投影链构造端点，再显式传入路径确认且实测过的墙段；这条数据适配和实车 session 评估尚未实现。

对 `(1,2)` session 的原始 LaserScan 做只读投影后，路径终点 `(0,4) N` 的目标线段（`y=2.0m, x∈[0,0.4]`）在 1,477/1,477 帧均有 5–9 个回波落入 ±0.04m 带内；沿墙观测范围中位数约 0.385m。逐帧拟合线斜率中位数约 0.00824（约 0.47°）。相对理想 `y=2.0m` 线的点到线绝对距离 p50/p90/p95 为 7.36/11.59/12.08mm；另按每帧拟合线计算，帧内绝对拟合残差 p95 的跨帧中位数为 13.24mm、p95 为 18.49mm。两种残差定义不同。该证据支持“这段终点墙在该姿态下被稳定观测”，但车在整段采集中近似静止，因此帧间高度相关；它只覆盖局部可见段和一个墙方向，不能单独观测完整平面位姿，也不证明整面墙连续。仍需一段已确认的非平行墙共同拟合，并用保留数据验证校正量。

Mac 上无需安装 ROS，可用 Python 3 标准库从原始 rosbag2 SQLite 只读解码 LaserScan、Odometry 和 `/tf_static` 并复核该线段：

```bash
python3 software/tools/analyze_scan_edge.py field_data/20260930_212853_junction_NE_open_SW_wall \
  --axis y --coord 2.0 --along-min 0 --along-max 0.4 --tolerance 0.04
```

该命令只读 bag，不生成或覆盖 bag 内文件；输出包括逐帧支持、沿线范围和残差统计。

## 离线复核

从仓库根目录、ROS Humble 与工作区已 source 的终端运行：

```bash
./software/scripts/replay_scan_session.sh field_data/20260930_210036_entry_sidewall_N_2cell
```

脚本在隔离 ROS domain（本次为 77）中回放 session bag，调用同一 `scan_debug` 链，并在唯一 replay 子目录生成 summary；原始 bag 不被改写。本次 `(1,2)` 验证使用部署并构建后的当前 `scan_debug`。原始在线 summary 为 1,475 帧，replay 为 1,476 帧；目标边 `((0,4),N)` 的 UNIQUE 命中数为 4,838 对 4,842（replay 多 4），两边 OPEN 均为 0，整体 UNIQUE/AMBIG/NONE 比率相同。差异来自启动时序导致的首尾帧采样，不是逐帧或计数完全一致；因此 replay 与原记录在统计上接近，不能称为字节级或确定性计数复现。验收修复仍需对照真值边上的 WALL/OPEN，并检查开口边是否被错误屏蔽，不能只看脚本退出码。
